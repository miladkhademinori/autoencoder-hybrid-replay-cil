# Reproducing *Hybrid Replay* for Federated Class-Incremental Learning (ICLR 2025)

> Milad Khademi Nori, Il-Min Kim, Guanghui Wang. *Federated Class-Incremental Learning: A Hybrid
> Approach Using Latent Exemplars and Data-Free Techniques to Address Local and Global
> Forgetting.* ICLR 2025. [arXiv:2501.15356](https://arxiv.org/abs/2501.15356)

No reference code accompanies the paper, so everything here was re-implemented from its text
(Sections 3–5, Algorithms 1–2, Table 2, Figure 3), from the FCIL protocol it says it follows (MFCL,
Babakniya et al., NeurIPS 2023) and from the companion ICML 2025 paper on AHR, which describes
the same hybrid autoencoder in more detail. This document records what the paper specifies, what
we had to choose, and every place where the reproduction deviates.

**Results:** see [`results/RESULTS.md`](results/RESULTS.md). It is regenerated by
`scripts/aggregate.py` and compares every finished run with Table 2 and Figure 3.

---

## 1. What the paper specifies, and where it lives in the code

| Paper | Implementation |
|---|---|
| Benchmarks `A/B/C/D` = tasks / classes per task / clients / active clients per round: CIFAR-100 10/10/50/5 and 20/5/50/5, ImageNet-Subset 10/20/100/10 and 20/10/100/10, TinyImageNet 10/5/300/30 | `hr_fcil/config.py::BENCHMARKS` |
| Each task's data split across clients by LDA, α = 1 | `hr_fcil/data.py::lda_partition` (FedML/MFCL per-class Dirichlet) |
| Encoder f(): ResNet-18; decoder g(): four-layer CNN | `hr_fcil/models.py` (ResNet-18 with a 3×3 stem as in MFCL; decoder FC → 2×[upsample, conv, BN, LeakyReLU] → conv → sigmoid, **1.41 M parameters**, matching the 1.4 M decoder of Table 3) |
| Loss: ELBO + λ Σ‖z − p_y‖² (Eq. 7) | `HRTrainer.local_update` |
| Server places the new task's class centroids with the Lennard-Jones potential (Eqs. 8–9, Alg. 1 l. 6–8) | `hr_fcil/alignment.py::lj_align`, `HRTrainer.place_new_centroids` |
| Clients send unaligned centroids = mean of f(θ_{h−1}, T_h) per class (Alg. 2 l. 12–13) | `HRTrainer.place_new_centroids` |
| FedAvg θ ← (1/I) Σ θ^c (Alg. 1 l. 13) | `hr_fcil/hr.py::fedavg` |
| Replay: decode latent exemplars with g(θ_{h−1}) where the client has memory for a class; otherwise decode p_j + N(0, σ²) (global replay, Alg. 2 l. 5–9) | `HRTrainer.build_replay` |
| KD: ‖f(θ_{h−1}, D_h) − f(θ_h, D_h)‖ + ‖g(θ_{h−1}, f(θ_{h−1}, D_h)) − g(θ_h, f(θ_h, D_h))‖ (Alg. 2 l. 19–21) | `HRTrainer.local_update` |
| Memory update: re-encode M ← f(θ_h, g(θ_{h−1}, M)), add random samples of T_h; fixed memory (iCaRL) | `HRTrainer.update_memories`, `ClientMemory.reduce` |
| Classification: argmin_j ‖f(x) − p_j‖ | `HRTrainer.evaluate` |
| 200 latent exemplars per class (HR) vs 20 raw exemplars per class (exemplar baselines) | `memory_size=20000` latent codes per client (= 200/class at 100 classes; 307-d codes are 10× smaller than 3072-d images, the same memory as 2000 raw images) |
| Ablations: HR-mini (10× less memory), w/o latent exemplars, w perfect exemplars, w/o KD, w/o global replay, w RFA | `hr_fcil/config.py::VARIANTS` |
| SGD at the clients; 10 random initialisations; mean ± SEM | `lr 0.1 → 0.01` exponential decay per task (MFCL); `scripts/aggregate.py` reports mean ± SEM |

**Metric.** Table 2 reports the *final* accuracy on all classes after the last task. The
per-task accuracies plotted in Figure 3 (recovered from the vector graphics of `do.pdf` in the
arXiv source; see `configs/paper_results.json`) end at the Table 2 value, for example 65.12
against 65.84 ± 0.57 for HR on CIFAR-100. We report final accuracy, the average incremental
accuracy, average forgetting and the whole per-task curve.

## 2. Details the paper leaves open, and our choices

| Detail | Choice | Why |
|---|---|---|
| Rounds per task Ω, local epochs E, batch size | Ω = 100, E = 5, B = 32 | Ω and B follow MFCL. E = 5 makes 100 rounds × 10% participation × 5 = **50 epochs per task**, the "# Epochs = 50" reported for HR on CIFAR-100 in Table 3. MFCL itself uses E = 10. |
| Learning rate, momentum, weight decay | 0.1 → 0.01 exponential decay within every task (MFCL); momentum 0.9; wd 5e-4; grad-norm clip 10 | MFCL / standard ResNet-18 recipe. |
| Latent size | 307 = 3072/10 | AHR paper (Table 4): compression ≈ 10, which also gives HR's "10× more exemplars for the same memory". |
| Loss weights | ELBO with Gaussian decoder (sum of squared errors) and KL weight 1; **λ = 100**; KD weights 1 | The paper writes the plain sum. All terms are divided by the input dimension (3072) so that SGD with lr = 0.1 is stable; this rescales the learning rate and leaves the relative weights unchanged. λ was chosen with the centralised check `scripts/calibrate.py` on task 1 ([log](results/calibration/task1_lambda_sweep.txt)): nearest-centroid accuracy after 4 epochs was 26.6–28.7% (λ = 1, stopped after 2 epochs), 46.9% (λ = 10), **54.3% (λ = 100)**, ≈50% (λ = 300, 1000); a cross-entropy ResNet-18 with the same budget reached 38.2%. λ = 100 also gave the lowest reconstruction error. |
| LJ parameters | ε = 1, σ = 5, gradient descent with lr 1 and step capped at 0.05σ, 3000 steps | Only the ratio of σ to the posterior spread matters. With σ = 5 the new centroids settle at ≈ 2^{1/6}σ ≈ 5.6 from their neighbours, far outside the encoder's posterior noise. Previously placed centroids never move (as in AHR). |
| Unaligned centroids | Collected from the round's I selected clients (Alg. 1 l. 5–6). If a class is missing among them, one more client is asked until every new class is covered. | Alg. 1. |
| Noise for synthetic samples, σ | 1/√(1 + 2λ) | The posterior std that minimises KL + λ·E‖z − p‖², i.e. the spread the decoder was trained on. |
| Number of synthetic samples per absent class | Mean number of exemplars per class in that client's memory (balanced replay); without memory, the client's mean number of samples per class of the current task | Not specified. |
| Which exemplars enter memory | Random (Alg. 2 l. 25); per-class quota = memory_size / #classes seen (fixed memory; fractional quotas are assigned to a fixed random subset of classes) | Paper. |
| **What "200 latent exemplars per class" counts** | Two readings, both run: **`paper`** = per client (memory_size 20000 latent codes per client, as GLFC's per-client memory of 2000 raw images = 20/class); **`paper_fedmem`** = per class across the whole federation (200 × 100 classes / 50 clients = 400 latent codes per client; HR-mini 40; perfect exemplars 400 raw) | See §3, item 6. |
| Augmentation | Random crop (pad 4) + horizontal flip on all training images, real and replayed | Standard for CIFAR. |
| Client selection | I clients drawn uniformly at random **every round** | Alg. 1 draws the clients once per task (l. 5, outside the round loop). Then only 10% of each task's data would ever be used, which cannot give the 84.8% first-task accuracy of Fig. 3, so we read l. 5 as the usual per-round sampling (MFCL). |
| Class order | Seeded random permutation per run | Standard. |

## 3. Issues found in the paper while re-implementing it

1. **Eq. 9 ascends the LJ potential.** As printed, the update
   `p ← p − η Σ 24ε [2σ¹²/r¹³ − σ⁶/r⁷] (p − p′)` moves p *towards* p′ when the pair repels, i.e.
   it increases U, and (p − p′) is not normalised by r. We use gradient descent on Eq. 8:
   `p ← p − η ∂U/∂p` with `∂U/∂p = Σ 24ε [−2σ¹²/r¹⁴ + σ⁶/r⁸](p − p′)`.
2. **Client selection once per task** (Alg. 1 l. 5); see above.
3. **TinyImageNet 10/5/300/30** uses only 50 of the 200 TinyImageNet classes. The client
   numbers match MFCL's SuperImageNet-L setting (300 clients, 30 per round, 5 classes per task),
   while MFCL's TinyImageNet setting is 10 tasks × 20 classes with 100 clients. We follow the
   paper as written (10 × 5).
4. **ELBO vs deterministic autoencoder.** The ICLR paper uses a VAE-style ELBO, while the ICML
   AHR paper explicitly rejects a VAE and uses a deterministic autoencoder. We follow the ICLR
   paper, and our λ choice makes the posterior nearly deterministic (σ_post = 1/√(1 + 2λ)).
5. **"HR-mini w 10× less memory"** is described in the text as HR *without* latent exemplars
   ("even without latent exemplars (denoted as HR-mini …) … relying solely on synthetic data
   generation"), but the ablation paragraph describes it as a 10× smaller memory budget. We use
   the latter (memory_size 2000 instead of 20000); the data-free variant is "HR w/o Latent
   Exemplars".
6. **The memory budget does not bind under the stated data split if it is per client.** With
   LDA(α = 1) over 50 clients, a client holds ~100 images per task: the median client/class
   pair has 8 images, the 90th percentile 25, and 12.6% of pairs are empty (measured with
   `lda_partition`). A per-client memory of 200 (HR) or even 20 (HR-mini, raw baselines)
   exemplars per class therefore stores almost all local data, so memory size would barely
   matter. Yet Figure 3 shows accuracy rising steadily from 1 to 128 exemplars per class, and
   Table 2 shows a 5.4-point gap between HR and HR-mini. Both patterns are consistent with
   counting exemplars per class across the whole federation. The paper does not say which
   convention it uses, so we run both.

## 4. Compute, and how to run

One full CIFAR-100 10/10/50/5 run is ≈ 13.8 M sample passes through the encoder, decoder and
KD teacher (100 rounds × 5 clients × 5 epochs × ~100·h samples, summed over tasks h = 1…10).
The paper reports 682 min per run on its GPU (Table 3).

```bash
pip install -r requirements.txt
# one run (GPU recommended)
python run.py --benchmark cifar100_10_10_50_5 --variant hr --seed 0 --amp
# the whole queue, resumable, two jobs per GPU
python scripts/run_queue.py --queue configs/queue_colab.txt --results_root results --amp --parallel 2
# tables
python scripts/aggregate.py --results_root results --markdown results/RESULTS.md
```

`notebooks/HR_FCIL_colab.ipynb` does the same on Google Colab and writes to Google Drive, so
runs survive disconnects.
